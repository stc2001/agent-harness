### 已独立验证（通过）

- **全量测试**（真实工作区切分支）：`.venv/bin/python -m pytest tests/ -q` → **823 passed, 2 skipped, 0 failed**（93s）。`main` 基线 800+2，净增 23 项全绿，**无回归**。

### 必须修复（阻塞）

**P1. `_cost` 与「装配器实际发出的消息」仍有 4 类不一致**（探针实测：`_count_tokens` 替换为 len 的精确计数；`.scratch/probe_i51_cost.py` 可复跑）

| 场景 | `_cost` | 实际发出 | 问题 |
|---|---|---|---|
| `agent_failed`（`harness/prompt_assembly.py:904` 发 `[tool error] …` 用户消息） | **0** | ~90 | 低估 |
| 未被 `agent_thought` 覆盖的 `tool_called`（`:877` 发 assistant tool_call） | **0** | ~115 | 低估 |
| 末轮 `agent_thought`(content) + `agent_completed`(output 同文) | 360 | ~230 | **高估**（`:797/:808/:837` 的 skip 逻辑未在 `_cost` 体现，content 计两次） |
| `memory_summary`（`:918` 发 `[memory] ` 前缀） | 100 | 109 | 低估前缀 |

`_cost`（`:442`）是预算的唯一判据：低估会导致**实际请求超限**，高估会导致**过早截断**。本 MR 的核心主张「只计实际发送」在这些路径上不成立。

**P2. 未披露的语义变更（藏在 `8629612` 内，issue/MR 均未提）**
- `harness/interfaces.py:136`：`AgentSpec.max_tokens` 默认 `16384` → `None`（请求省略该字段）；`impl.py:232` 条件传参。
- `harness/llm_driver.py`：新增 `DeepSeekDriver`（`thinking` 发 `{type: enabled|disabled}` 结构体），`_BACKEND_DEFAULTS` 增加 `deepseek`/`passthrough`。
两项均不在 issue 验收标准内，MR 自检「验收标准逐条对应 issue」对其不成立。请**要么**补进 issue/MR 的变更摘要、影响面、验收标准（含「默认无 max_tokens 对调用方的影响」），**要么**拆出为独立 issue/MR 单独评审。

**P3. `max_tokens=None` 使 `hard_limit` 失去输出预留（与 ADR-053 修订矛盾）**
`harness/prompt_assembly.py:575`：`hard_limit = context_window - max_tokens if max_tokens else context_window`。探针（`context_window=1000`）：`max_tokens=None → hard_limit=1000`（无预留），`max_tokens=100 → 900`。ADR-053 修订写明 `hard_limit = context_window − max_tokens（物理上限，含输出预留）`；默认改 None 后默认路径**不再预留任何输出预算**，prompt 可填满整个窗口，provider 叠加输出即有超限风险。请给出方案（保留可配置的输出预留默认值，或明确「无限输出时无预算保证」并写入 ADR/测试）。

**P4. 测试边界过松、缺上述用例**
`tests/test_cost_measurement.py:65/113` 允许 `1.25x` / `1.35x` 误差，恰好掩盖 P1 的漏计/双计。请收紧到能抓住这些差异，并补：`agent_failed`、未覆盖 `tool_called`、末轮 skip、`memory_summary` 前缀、`agent_started._retry_error` 五类用例。

## R2 修正（2026-10-19，重提）

修复提交：`afd2be9`。R1 评审提交 `de6e98a` 保留为分支祖先（未 rebase/force）。

### P1 — `_cost` 与发射映射统一（精确探针，`_count_tokens = len`）

| 场景 | `_cost` | 实际发出（事件消息，不含 system） | 结果 |
|---|---|---|---|
| `agent_failed`（`[tool error] …`） | 90 | 90 | ✅ |
| 未覆盖 `tool_called`（assistant tool_call） | 115 | 115 | ✅ |
| 已覆盖 `tool_called`（agent_thought 携带同 id） | 36 | 36 | ✅ |
| 末轮 `agent_thought` + `agent_completed`（同文） | 230 | 230 | ✅ |
| `memory_summary`（`[memory] ` 前缀） | 109 | 109 | ✅ |
| `agent_started._retry_error` | 44 | 44 | ✅ |

说明：Lead 探针的 `sent` 含 `system`（"sys" 3 tokens），故原探针会显示 `cost = sent - 3`；事件消息本身**逐字节相等**。实现上 `build_messages` 先按同一映射计算逐事件成本（含 skip/coverage/orphan 判定），`_cost` 在 build 之后复用该结果。

### P2 — 已披露的语义变更（保留，不回退）

- `AgentSpec.max_tokens` 默认 `None`：请求 kwargs **省略** `max_tokens`，由后端默认输出上限；app 显式设置时按显式值发送。影响：依赖旧 16384 默认的调用方需显式配置；预算侧由 P3 的 `output_reserve_tokens` 独立保证。
  - 绑定测试：`test_spec_max_tokens_defaults_to_unlimited`、`test_unlimited_max_tokens_is_omitted_from_the_request`（`tests/test_agent_runtime.py`）。
- `DeepSeekDriver`：`driver/backend = deepseek` 时，`thinking=True/False` 发 `{"type": "enabled"/"disabled"}`，`None` 不发送字段（布尔值实测 422）。
  - 绑定测试：`test_deepseek_driver_renders_thinking_as_an_object`、`test_deepseek_driver_no_opinion_sends_no_thinking_field`、`test_deepseek_driver_never_sends_a_boolean`（`tests/test_llm_driver.py`）。

### P3 — 独立输出预留（`max_tokens=None` 语义不变）

`AgentSpec.output_reserve_tokens: int = 16384`（app 层，profile/调用方可覆盖）；仅用于预算：

```
reserve    = max_tokens if max_tokens is not None and max_tokens > 0 else output_reserve_tokens
hard_limit = max(1, context_window - min(reserve, max(0, context_window - 1)))
```

探针：`ctx=100000, max_tokens=None, reserve=16384 → hard_limit=83616`；`max_tokens=100 → 99900`；`ctx=1000, reserve=16384 → hard_limit=1（effective 999）`。
测试：`tests/test_context_round_truncation.py::test_output_reserve_applies_when_max_tokens_is_omitted`、`test_explicit_max_tokens_wins_over_output_reserve`、`test_output_reserve_never_makes_hard_limit_nonpositive`、`test_agent_spec_output_reserve_reaches_the_preview_hard_limit`。

### P4 — 测试收紧

`tests/test_cost_measurement.py` 全部改为**精确相等**（不再 1.25x/1.35x），新增 5 类边界 + 孤儿 tool_result 用例；`tests/test_context_round_truncation.py` 新增 4 项输出预留测试。
