### 必须修复（阻塞）

**P1. `_observe` 硬编码 `"deepseek"` provider**（`scripts/memory_bridge.py:323,335`）

```python
usage = sum(_count_tokens(str(m.get("content") or ""), "deepseek") ...)
cost = _count_tokens(str(e.payload.get("tool_calls") or ""), "deepseek")
```

`preview_llm_messages` 的返回里已有 `params.provider`（实际装配用的 provider），但这里写死 `deepseek`：
- 直接违反 issue 验收标准「不在 app 代码里写死 `deepseek` provider/model service」；
- 在本地模型/CJK 下，回退 tokenizer 对中文计 **0**（实测 `_count_tokens("任务说明","deepseek") == 0`）⇒ usage 被低估，高水位可能永不触发——正是本 MR 要修的失效类型。
**修**：从 `out["params"]["provider"]`（或 profile 解析）取 provider，usage 与 rounds 两处都用它；补 CJK/provider 测试。

**P2. usage 漏计 tool_call arguments（及 reasoning_content）**

`_observe` 的 usage 只累加 message 的 `content`；assistant 消息的 `tool_calls[].function.arguments` 完全没计。探针（len 计数）：同一请求 `usage=23` vs `content+tool_call args=48`；tool-heavy 轮次里 assistant content 常为空 ⇒ 该轮成本被算成 0。预算判据是 `meta.budget_tokens`，而 usage 这样低估 ⇒ 高水位/低水位判断系统性偏晚。
**修**：按装配器实际发出的字段计（content + reasoning_content + tool_call arguments；与 `preview` 的 messages 一一对应），或复用/暴露一个一致的成本口径；补 tool-heavy 用例。

**P3. 旧站点方法残留 + `_last_size` 未初始化**

`_compact_prefix` / `_compact_suffix` / `_should_compact` / `_do`（`scripts/memory_bridge.py:423-481`）已无任何调用方，但 `_should_compact` 读 `self._last_size`，而 `__init__` **从未初始化** `_last_size` ⇒ 一旦被调用即 `AttributeError`（实测）。issue 验收标准要求「触发判据单一权威：删除站点里重复的旧判据」——这些正是旧站点逻辑，应删除（`_unused_done_boundaries` 同）；若确需保留为 app API，必须初始化并补测试。

**P4. 测量接缝零真实测试**

`tests/test_memory_state_machine.py` 把 `_observe` 整个 monkeypatch 掉（`:94`、`:195`），即 P1/P2 所在的测量代码**完全没有测试**——这属于「测试存在 ≠ 测试有效」。请补 `_observe` 的真实用例：provider 跟随 preview 的 `params.provider`、tool_call arguments 被计入、回退 tokenizer 下 CJK 不再计 0、无 server 时的 provider 选择。

`changes-requested` —— P1–P4 修复后重提 R2；R2 附：`_observe` 新测试与探针结果、旧站点方法删除/初始化说明、全量仍绿。
