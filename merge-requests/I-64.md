## 1) per-build cost 上下文

- `build_messages(..., cost_map_out=dict)`：调用方传入可变 dict，build 填充本
  build 的 `(id(event), passback) -> (event, cost)` 快照（强引用事件，防 id 复用）。
- `_cost(ev, ..., cost_map=...)`：显式上下文；无显式 map 时回退全局
  `_LAST_COST_MAP`，**契约已写入 docstring/注释：仅最近一次 build 精确**；
  交错/并发使用方必须传显式 map。
- 全局 map 读写加锁（兼容回退不再有数据竞争；精确性仍以显式 map 为准）。
- 测试：
  - `test_cost_map_out_is_per_build_and_interleaved_builds_stay_exact`：
    两次 build 后分别用各自 map 求 `_cost`，总和 == 各 build 输出成本；fixture 含
    `tool_called` pairing 上下文，忽略显式 map 会失败。
  - `test_cost_map_out_is_safe_across_concurrent_builds`：每线程不同事件集 +
    各自 map，断言各自总和；不依赖全局状态。

## 2) 小窗口 reserve 钳制

```
reserve_cap       = max(1, ceil(context_window / 4))
effective_reserve = min(reserve, reserve_cap)   # reserve = max_tokens 或 output_reserve_tokens
hard_limit        = max(1, context_window − effective_reserve)
```

- `max_tokens` 的**请求字段原值不变**；只有预算有效预留被钳制；meta 同时报告
  `output_reserve_tokens`（原始）与 `output_reserve_effective`（钳制后）。
- 3200 窗口 + 默认 16384 → effective 800、hard_limit 2400（high water 可达）；
  6000 窗口 + max_tokens 2000 → effective 1500、hard_limit 4500；100K/16384 不受影响。
- 测试：`test_output_reserve_is_capped_to_a_quarter_of_the_window`、
  `test_tiny_window_keeps_a_reachable_high_water_mark`、
  `test_explicit_max_tokens_is_also_capped_for_tiny_windows`、
  `test_output_reserve_applies_when_max_tokens_is_omitted`（大窗口）；
  `test_output_budget_is_reserved` 按新语义更新为 4500（保持精确断言）。
- I-51 旧断言 `effective=window-1` 替换为 1/4 钳制（原断言与新规则直接冲突，
  理由：旧规则使 tiny window prompt 不可用）；未使用源码 grep 断言。
- ADR-053 追加 I-64 规则与理由。

### 独立验证（全部通过）

- **范围**：`harness/` 仅 `prompt_assembly.py`；tests 3 文件 + ADR-053 + MR；`pi/`/translate/merge_TODO/部署物零 diff。
