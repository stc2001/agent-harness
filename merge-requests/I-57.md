## 变更摘要

ADR-001 修订落地：app 侧记忆策略收敛为**单插槽 / 单链**，harness 侧保持两位置机制不变。

- **单插槽**：`SLOT = "before_task"`；新摘要必须与上一份**合并**（PREVIOUS SUMMARY），
  不再按 region 分链；`previous_summary()` / `slot_count()` 保留 region 参数但忽略。
- **取段顺序**（ADR-001 §4.2）：`_observe` 返回 `(budget, usage, rounds, prefix_count)`；
  更早任务 prefix 最旧优先，prefix 不足再 suffix 最旧；当前任务至少保留 1 轮。
- **尺寸守卫**（ADR-001 §4.4，DSH 同款）：`framed(<mem>摘要) >= shadowed(被遮蔽 span)`
  ⇒ 拒绝、不注入、计失败；`shadowed` 用公开 `memory.count_tokens`，保留 preview provider。
- 删除 `--threshold` 旋钮与旧站点死代码（I-53 R2 已删，不复活）。
- 保留 I-53 R2 的 `_observe` provider/完整字段语义与 I-56 公开面。

### P2（阻塞：行为与文档不一致）单插槽下，混合/suffix span 的摘要不移除任何事件

G 的取段顺序允许 span 跨入 suffix（"prefix 不足再 suffix 最旧"），但 `_summarise_span` 用 `span[-1]` 作 `after_event_id`，而 harness 的 fold 是 **per-slot** 的：`before_task` 只折叠 **prefix 内**的边界。独立探针（`build_messages`）：

```
无摘要                      : OLD-PREFIX-KEPT? … Task … 3 个 suffix 轮
mixed span(boundary=t2)     : OLD-PREFIX-KEPT? … <mem>SUM</mem> … Task … 3 个 suffix 轮   ← 什么都没折掉，反而+摘要
pure prefix(boundary=p1)    : <mem>SUM2</mem> … Task …                                    ← prefix 正确折叠
```

即：当 span 含 suffix 轮（或以 suffix 轮收尾）时，摘要**只增不减**；而 `_tick_dropping` 的投影按"这些轮会被移除"来估算到低水位，与实际装配脱节；状态机又没有迟滞保护 ⇒ 调用方若每步调用 `step`，usage 仍 ≥ 高水位时会**反复压缩/合并**（每次一次 summariser 调用）。

要求（二选一或组合）：
1. **真正释放**：让 suffix 轮的折叠走 `after_task` slot（或给 before_task 传"prefix 内边界"，suffix 轮另走机制），保证摘要确实替换被遮蔽内容；
2. **或明确契约并测试**：若设计是"摘要先存证、suffix 轮由 harness 截断在超限时释放"，请把该机制写进 ADR-001（谁在何时释放、低水位投影如何对应），并补一个**端到端测试**（真实 `build_messages`，断言注入后组装产物/成本符合预期），再加防重复触发的保护（如注入后记录 usage、未回落不重复压缩）。

### 非阻塞

- 若采纳上述 P2 方案 1，注意与 F 的 per-slot floor 语义一起更新 ADR-001。

## R2 修正（2026-10-19，重提）

修复提交：`e3e65ba`（`a602b3e` 文档）；评审提交 `bdd5e48` 保留为祖先（未 rebase/force）。

### P1 — 两处 HOME 隔离（阻塞）

`test_inject_summary_accepts_both_positions_over_the_public_surface` 与
`test_unknown_slot_is_refused` 接入 `_isolate_home(tmp_path, monkeypatch)`，
设置 HOME/XDG_CONFIG_HOME；registry 不再写 Lead 不可写的 `~/.harness/instances`。

### P2 — suffix/mixed span 真正释放（选择方案 1）

根因：harness 的 fold 是 **per-slot** 的（before_task 只折 prefix，after_task 只折
suffix），而旧实现无论 span 是否含 suffix 都只写 before_task；混合 span 的
boundary 落在 suffix ⇒ 什么都没折掉，摘要反而增加上下文。

修正（harnes 零改动）：
- 按选中 span 的实际区域写位置：prefix → `before_task`，suffix → `after_task`；
  **混合 span 将同一份合并摘要写入两个位置**（一个链/一份摘要，两个释放点）。
- 低水位投影与实际释放一致（每个被选轮次都被对应 slot 折叠）。
- 尺寸守卫按**插入副本总数**比较：`framed * placements >= shadowed` 拒绝；
  shadowed 计入被选轮次关联的 `tool_result`（原先只算 thought 会低估）。
- 端到端测试：`test_mixed_span_injections_release_in_real_assembly` 用真实
  `build_messages` 断言 Task 保留、两个 `<mem>` 摘要参与装配；
  `test_mixed_span_writes_both_positions_and_collapses_task` 断言两 slot/boundary
  分属 prefix/suffix。
- ADR-001 增补「单摘要/单链不变；位置数 = 被选区域数（1 或 2）」的释放契约。
