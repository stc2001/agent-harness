## 变更摘要

ADR-053 二次修订：压缩策略归 app，harness 只保留机制。

- 两个固定插槽 `before_task` / `after_task`；`<mem>` 占位符由 harness 渲染；
  装配顺序 `前序任务 → slot_before → Task → slot_after → 当前轮次`；
  SYS 与 Task 永不截断；每个 slot 只取最新（顶层读规则）。
- `inject_summary(session_id, content, *, slot, after_event_id=None)`：`slot` 必填。
- 审计拆级（**supersedes I-51 的 `prompt_truncated`**）：
  - 丢弃历史后装得下 → `history_context_truncated`（warn）
  - 无历史可丢仍超限 → `over_budget_unresolvable`（error）
  - 两者 detail 含 `preserved: ["system","task","memory_slots"]`
  理由：umbrella 事件把「常态兜底」与「配置错误」混在一起，且
  `prompt_truncated` 名不符实（SYS/Task 不截断）。
- 删除死机制 `client.memory.compress()` 与 `memory-compressor` spec。
- 新增公开面：`sessions.events.logical`、`memory.count_tokens`、`config.profile(s)`。

### 阻塞项（必须修复后才能合并）

**P1. 全量测试失败 3 项**（作者声称 144 子集通过，但该子集未包含这些文件；默认「894 passed」实际为 `2 failed → 892 passed`）

1. `tests/test_cost_measurement.py::test_memory_summary_prefix_is_counted` —— **I-51 遗留测试未更新**：仍断言 `[memory] ` 前缀（现在是 `<mem>…</mem>`），且无 `slot` 的 summary 被装配忽略：`Σ_cost=31 != Σ_sent=0`。需更新该测试（用 `slot=` 注入，断言 `<mem>` 成本），并补「无 slot 的 summary 被忽略」的明确用例。
2. `tests/test_memory_slots.py::test_injecting_the_same_slot_twice_keeps_only_the_newest` —— 失败在 `c.agents.register(spec)` 写 `~/.harness/instances/…`：测试只设了 `HARNESS_HOME`，但 registry 用 `Path.home()`（`sdk/client.py:52`）；在 Lead 沙箱 HOME 不可写 ⇒ PermissionError。需 `monkeypatch.setenv("HOME", str(tmp_path))`（并清 XDG 等），或改用 store/session 直接构造、避免 registry。
3. `tests/test_memory_slots.py::test_app_can_read_the_logical_event_view_without_private_names` —— 同上 HOME 隔离问题。

**P2. 严重：slot 摘要带 `after_event_id` 时吞掉 Task 锚点**

探针（`build_messages`，`after_task` slot 摘要带边界）：

```
[no boundary]  Task 存在: True   <mem> 存在: True
[boundary=t1]  Task 存在: False  <mem> 存在: True   ← 只有 SYS + 历史 + mem
[boundary=r1]  Task 存在: False  <mem> 存在: True
```

原因：`harness/prompt_assembly.py` 的 cutoff 用 `memory_summaries[0].payload["after_event_id"]` 直接切掉该 id 之前的**所有**事件，包括 `agent_started` 锚点；锚点丢失后不再生成 `Task:` 消息。这直接违反本 MR 的「SYS 与 Task 永不截断」，也与 I-53 app 的实际行为冲突：`memory_bridge._inject()` 对 prefix/suffix **都**传 `span[-1]`，第一次压缩后 Task 锚点就会消失。另：多 slot 时只取 `memory_summaries[0]` 的边界，语义不清。

要求：
- 定义清楚的 per-slot 边界语义，且**无论边界在哪，Task 锚点都必须保留**（例如先确定最新 anchor，再在 cutoff 结果中保留/重插锚点；或 before_task 才作全局 cutoff、after_task 用显式丢弃集合）；
- 补测试：before_task/after_task × 边界在锚点之前/之后、两个 slot 各一条摘要、以及「压缩后 Task 仍存在」。

**P3. `client.config.profiles()` 是坏的**

`harness/sdk/client.py:1290` `from harness.sdk.config import available_llm_profiles` —— 该函数**不存在**（`sdk/config.py` 只有 `resolve_llm_profile`），调用必抛 `ImportError`；且无测试覆盖（只测了 `config.profile(name)`）。请实现 `available_llm_profiles`，或删除 `profiles()`；保留则必须补测试。

**P4. 旧 guard 已空转**

`tests/test_truncation_is_fallback_only.py:192` 仍断言 `"prompt_truncated" in src`——现在该字符串只存在于 `impl.py` 的**注释**里（`:376`），guard 不再证明任何 emitted event，且与本 MR 的 supersede 矛盾。请改为断言 `history_context_truncated` / `over_budget_unresolvable` 的 emitted 行为，并断言不再 emit `prompt_truncated`。

**P5. 旧格式 summary 静默消失（需决策/文档）**

已有会话里 `memory_summary` payload **没有 `slot`**（I-53 之前/中间产物）会被装配**静默忽略**——升级后这些摘要从上下文消失。请明确处理：迁移映射（如缺省 `before_task` + 审计 warn）或至少写入 ADR/issue 的兼容性说明，并补「无 slot 被忽略」的显式测试。

- 测试数 delta 需在修复后重新给出（当前实际是 3 failed / 892 passed / 3 skipped）。
