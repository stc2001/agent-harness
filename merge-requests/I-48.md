## 变更摘要

处理 I-47 复评留下的两项遗留。**采纳方案 A**（可见告警），未做方案 B（opt-in 远程端点）
——理由见下。loopback 判定逻辑本身**未改**（issue 明确排除）。

**(a) docstring 与代码/测试三者矛盾（低）**：原句「a non-loopback result is refused
**unless it came from an explicit override**」与同文件第 89–90 行、代码
（`else: url = None  # explicit but remote: still refuse`）、以及
`test_remote_env_override_is_refused*` 全都相反。运行时零影响，但**后来者若照该句
把代码「改对」，就会重新打开 prompt 原文外发**这一已修复缺陷。已改写为明确
「**包括显式 override 也拒绝**（fail-closed）」，并把拒绝不静默的语义写进 docstring。

**(b) 非 loopback 自托管静默降级（中）**：门控只放行 loopback，因此 llama.cpp 部署在
**同局域网另一台机器**时 `_tokenize_url()` 返回 `None`，**静默**回退到 CJK 盲的 HF
tokenizer ⇒ 中文仍计 0，且无任何日志/告警信号。现改为：

- 因**拒绝**而不可用（profile 派生非 loopback，或显式 override 指向远程）⇒
  `warnings.warn(UserWarning)` **每进程一次**（模块标志 + warnings 机制双重去重，
  避免一轮 ~43 次计数刷屏）；
- 同时把原因记录到模块级 `_TOKENIZE_DISABLED_REASON`，供诊断读取；
- **显式 `HARNESS_TOKENIZE_URL=off` 不告警**（那是使用者的有意选择，非降级）；
- 告警文本给出可执行指引（「在 loopback 跑服务，或把 HARNESS_TOKENIZE_URL 设为 loopback 端点」）。

### 非阻塞提示（不归责本 MR）
