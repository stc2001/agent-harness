## 交付内容

### 1. usage 回落观测

- 数据源与字段：`run.json` / `meta.json` / `observe.csv` / `memory.jsonl`
- 关键口径：
  - `observe.csv.assembled_cost` **仅 content**（不含 reasoning/tool args）；
  - `memory.jsonl.cost_before` 是触发时的**完整 usage**，与 `PiMemory._observe` 同口径；
  - 直接对比两者会误判「未回落」。
- 期望序列：85% 高水位 → 一次 drop 到 25% → 下一步完整 usage 接近低水位 →
  再增长；`dropped_rounds` 持续 >0 表示 harness 兜底截断在兜底。
- 可复制命令：CSV/jq 查看、Python 压缩前后对比、完整 usage 重算 snippet
  （公开 SDK：`preview_llm_messages` + `memory.count_tokens`）。
- 异常清单：compactions=0（预算/tokenizer/记忆开关）、无 memory.jsonl
  （尺寸守卫拒绝，查 stderr）、slot 数量、usage 不回落/反复压缩、harness 截断。

### 2. 旧 summary 迁移

- 检测：preview `meta.ignored_legacy_summary_count` + logical events 列举；
- 迁移：按 ADR-001 region 重新 `inject_summary(..., slot=...)`：
  prefix→`before_task`、suffix→`after_task`；旧事件留审计（不装配≠删除）。
- **计数边界（如实记录）**：在线 API append-only，旧无 slot 事件不会被删除，
  新增 slot 摘要不会让 `ignored_legacy_summary_count` 归零；验收应为
  「count 不增长 + 新 `<mem>` 正常装配」。若合规要求物理归零，需离线会话
  store 迁移（破坏性，另行评审），不能为掩盖计数删除审计事件。

### P1（阻塞）runbook 需补「resume 会覆盖产物」的真实边界 —— 并暴露一个 app bug

核对代码发现（与本 MR 的文档描述不一致）：
- `pi/artifacts.py::append_memory` 在 `records` 非空时用 **`"w"`（truncate）** 写入，不是追加；`records` 为空时 `touch()` 保留旧内容（行为不一致）。
- `pi/runtime.py::run` 每次运行都 `self._rows = []`，并在结束时 `write_observe(self._rows)`（覆盖）。
- `--resume`/新进程是新的 `PiRuntime`/`PiMemory`（`self.memory.compactions` 从空开始）；因此 resume 后：
  - `observe.csv` 被覆盖为**仅当前 run 的步骤**；
  - `memory.jsonl` 在本次有压缩时被覆盖为**仅新 compactions**（丢失历史压缩记录）；无压缩时则保留旧文件（stale，易误读）。
- 这与 ADR-002 §3.6「每次压缩追加 `runs/<sid>/memory.jsonl`；每步观测追加 `observe.csv`」的措辞矛盾，也会让 runbook §1 的运维判读在 resume 场景失真。

要求：
1. runbook §0/§1 增补明确的 **caveat**：`observe.csv`/`memory.jsonl` 是 per-run 产物，`--resume`/新进程会覆盖（历史压缩事件以 session store 的 `sessions.events.logical` 为准；legacy 审计也在那里）。说明「有压缩时覆盖、无压缩时保留旧文件」这一当前行为，避免误导。
2. 该行为是**代码缺陷 vs 文档契约**的取舍，另开 **I-70**（示例：`I-70-run-artifacts-resume`）修复：二选一——(a) 真正追加（读旧记录合并、`observe.csv` 追加或按 run 分段目录）；(b) 明确 per-run 分段（`runs/<sid>/<run_id>/`）并更新 ADR-002 §3.6/runbook；补 resume 回归测试（旧 compactions/observe 保留或按约定分段）。**本 MR 仍保持 docs-only，不夹带代码修复**。
3. MR 记录里把「本 MR 仅文档」与「I-70 待修代码」分开写清。
