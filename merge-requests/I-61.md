`tests/conftest.py` 的 `_pi_fixture_tokenizer` 只设置 `HARNESS_TOKENIZER_DIR`，但 `_get_tokenizer(provider, "tokenizer_dir")` 的解析顺序是：**先看 cwd 相对路径** `tokenizer_dir/<provider>`，只有它不存在时才走 `HARNESS_TOKENIZER_DIR` / checkout 兜底。在 OH 工作区（以及任何带部署 tokenizer_dir 的 checkout）根目录跑 pytest 时，相对路径存在 → env 被忽略：

```
HARNESS_TOKENIZER_DIR=<repo>/tests/fixtures/tokenizer   → _get_tokenizer("deepseek","tokenizer_dir").encode("厦门朝日俱乐部") == 4
    （真实部署 tokenizer；fixture 应为 22）
```

请修（三选一，**推荐 1**）：
1. 在 conftest 里**直接把 fixture tokenizer 装进缓存**（确定性、仍走 fast loader/守卫）：
   `pa._TOKENIZERS["deepseek"] = pa._load_fast_tokenizer(str(fixture/deepseek 目录))`，yield 后 clear；并加一个小的自检（例如断言当前缓存 tokenizer 对 `厦门朝日俱乐部` 的计数与 fixture 一致，或 identity）。
2. 在 pi 测试期间 `monkeypatch.chdir` 到不含 `tokenizer_dir` 的临时目录（需确认 pi 测试不依赖 repo 相对路径）。
3. 若想让 `HARNESS_TOKENIZER_DIR` 真正优先，那是 **harness 语义变更**，请单独立项（不要塞进 I-61）；I-61 仍须保证测试 hermetic。

修后请提供：pi 测试在「fixture 生效」下的证据（CJK 计数=fixture 值 / 缓存 identity）、`pytest tests/test_pi_*.py` 与 OH 全量结果。

`HARNESS_TOKENIZER_DIR` 在带部署 tokenizer 的 checkout 上无效。修正为**直接装缓存**：

```python
pa._TOKENIZERS.clear()
tok = pa._load_fast_tokenizer(str(fixture_root / "tokenizer_dir" / "deepseek"))
pa._TOKENIZERS["deepseek"] = tok
assert pa._TOKENIZERS["deepseek"] is tok
assert len(tok.encode("厦门朝日俱乐部")) == 22
yield
pa._TOKENIZERS.clear()
```

仍走 fast loader + CJK 零值守卫；pi 测试结束后清缓存。
