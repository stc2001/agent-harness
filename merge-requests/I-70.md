## 语义选择与理由

**选 (b) per-run 分段**：`runs/<sid>/<run_id>/`，每次 `PiRuntime.run` 生成唯一
`run_id`，写入 `run.json`/`meta.json`。resume/新进程产生新段，旧段原样保留。

理由：audit 最清晰；不必给 observe.csv 改 schema/合并旧行；与「每次 run」天然
对齐；`read_meta` 只需取最新段。旧扁平 `runs/<sid>/{run.json,meta.json,observe.csv,memory.jsonl}`
保留为 **legacy 只读**（`read_meta` 回退），不自动迁移、不再写入。

## 实现

| 文件 | 变更 |
|---|---|
| `pi/artifacts.py` | `new_run_id()`；`session_dir`/`run_dir(..., run_id)` 分段；`RunSummary.run_id`；run/meta 写 run_id；observe/memory 写当前段；`read_meta` 最新段 + legacy flat 回退 |
| `pi/runtime.py` | `PiOutcome.run_id`；每次 `run()` 新 run_id/新段；meta 写 run_id；产物写当前段 |
| tests | artifact 路径改分段；新增 resume 回归；TUI 同一 session 两段断言 |

**旧产物处理**：legacy flat 保留只读；新 run 不再写它；不自动搬迁。
