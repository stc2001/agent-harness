## 变更摘要

修复沙箱/权限的 3 个真实缺陷，并把安全边界收敛到「挂载 + 内核 guard」：

1. `sandbox.execute()` 容忍非 UTF-8 输出（bytes + `errors=replace`），不再因日文输出
   让整次工具调用失败并破坏 tool_call 配对。
2. 文件权限判定改为 **fail-closed + 路径规范化**：未映射路径不再放行；`..`
   不再按字面前缀匹配，防止 `/ws/out/../src` 越权写只读树。
3. `bash` 按命令语义判定访问模式（只读目录下 `cat`/`ls` 不被误拒），源挂载
   显式 `mode: "ro"`；同时回退 pre-call 门的命令分类启发式（-523 行），门收敛为
   「读优先」咨询性检查，执行点交给挂载 + Landlock exec-guard。

### P1（阻塞）`_check_command_paths` 无限递归

`harness/tools/sandbox_exec.py:44-71`：

```python
    try:
        for path in paths:
            _check_access(path, permissions, "read", audit_log, path_map=path_map)
    except PermissionError:
        _check_command_paths(paths, permissions, audit_log, path_map)   # ← 递归自身
```

异常分支用**完全相同的参数递归**，而不是按 ADR-051 契约「读被拒 → 按 write 复检」。后果：任何**有 host 映射但不在 `file_access` 授权内**的路径（例如 `PATH_MAP={"/ws/x": "/tmp/x"}`、授权 `/tmp/x/`，命令 `cat /ws/xyz/f`）都会在读检查抛 `PermissionError` 后无限递归，最终 `RecursionError`。

实测（经公开 `bash` handler，非仅私有函数）：

```
RESULT: RecursionError via public bash handler -> BUG
```

这正是 ADR-051 注记里承诺的「仅在读被拒时才按 write 复检」没有落地；同时它把「明确的越权写应被提前拒绝」变成了崩溃。

**修复（已验证）**：异常分支应为逐路径的 write 复检：

```python
    except PermissionError:
        for path in paths:
            _check_access(path, permissions, "write", audit_log, path_map=path_map)
```

我在工作区临时应用该修复后：同一探针返回干净的 `PermissionError: Access denied — path '/ws/xyz/f' not in agent permissions`，且 `test_builtin_tools/test_access_boundary/test_exec_guard/test_sandbox_encoding` **54 passed, 1 skipped** 不变。

**要求**：
1. 修 `_check_command_paths`（1 行级改动 + 注释）；
2. 补回归测试：经**公开 handler**（bash 与 sandbox_execute 各一）对「映射但未授权」路径断言 `PermissionError`（而非 `RecursionError`），并断言合法只读读仍放行；
3. 该 bug 在源提交 `78737a3`/本地 HEAD 中同样存在（你只是忠实导入）；请顺手修正本地仓库，避免后续再被导入。

### P2（非阻塞）`_resolve_host_path` docstring 与实现不一致

`harness/tools/file_io.py:33` 声称「on BOUNDARY-aligned segments, so `/ws/xyz` does not match the prefix `/ws/x`」，但实现与测试都是**普通前缀匹配**（`/ws/xyz` 会解析成 `/tmp/xyz`，再由权限层拒绝——`test_sibling_prefix_resolves_then_is_denied` 正是这个语义），函数体内注释 `:48` 也写「Plain startswith matching is kept on purpose」。请让 docstring 与 ADR/测试一致（安全相关文档不应互相矛盾）。
