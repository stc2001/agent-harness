## 变更摘要

修掉「当前任务（suffix）不受任何上下文约束」这一根因：单任务长程下 suffix 永不截断，
请求带着超长 prompt 发出，服务端在**全额 prefill 之后**才用 400 拒绝（实测白付 204s）。

改为**按「完整轮」截断**（轮 = 一条带 `tool_calls` 的 `agent_thought` + 其全部
`tool_result`），prefix 与 suffix 用同一套规则；预算改为按**实际发出的 messages**度量
（含 `tool_result` 裁剪后的形态，旧口径对超大结果高估 2.4x–24x）；`memory_summary`
改为**事件级定位**并**计入预算**（原先固定插在任务锚点之后、且不计预算）；当
`SYS + mem(prefix) + 任务锚点 + mem(suffix) + 最后 N 轮` 这个**不可再精简集**仍超物理
上限时 **fail loudly**（写 `agent_failed` 并返回 `status="context_overflow"`），而不是
发出注定被拒的请求。

顺带修掉两个同源既有缺陷：prefix **逐事件**截断会切出**悬空 `tool` 消息**
（违反 ADR-052 §5 不变量 2，已实测复现）；`assemblable()` 只剥「缺结果的轮」而不剥
「缺调用方的结果」，两侧不对称。

## 影响面

- 触及模块：`harness/prompt_assembly.py`（核心）、`harness/interfaces.py`（新增
  `AgentSpec.context_min_keep_rounds: int = 1`）、`harness/prompt_preview.py`（透传
  `min_keep_rounds` / `max_tokens`）、`harness/agent_runtime/impl.py`（**meta 的首个消费者**）
- 行为变更（**有**）：
  1. 当前任务会**被截断**（此前 `keep ALL`）——这是本 MR 的目的
  2. 截断一律落在**轮边界**（此前 prefix 是逐事件）
  3. 预算口径改为**终态度量**（此前 `str(ev.payload)`）
  4. `mem` 落位改变（prefix 被丢光时从"锚点之后"移到"锚点之前"）+ 计入预算
  5. 支持 2 个 `mem`（prefix 区 / suffix 区）
  6. 不可满足时**不再静默发出**，改为可诊断失败
- 需要同步更新的文档/ADR：已在本 MR 内完成 —— 新增 **ADR-053**；ADR-034 加
  **Rev 4 注记** + 顶部 superseded 横幅（原文保留以维持审计链）；ADR-052 §5 不变量
  **由 4 条增补为 5 条**（新增"整轮边界"）；`CONTEXT.md` 新增「上下文预算与会话装配」
  小节，并把原「锚点」改称「沙箱锚点」以消歧（装配语境是「任务锚点」）
