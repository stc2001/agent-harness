## 变更摘要

在 fallback tokenizer 的**计数期**补零值守卫：已缓存/注入的坏 tokenizer 不再
对非空文本静默返回 0；server `/tokenize` 路径仍权威。

## 实现

- `_count_tokens` fallback：
  - `n = len(tok.encode(text))`
  - `text.strip()` 非空且 `n == 0` → `ValueError`，信息含 provider、实际
    tokenizer 路径（`_TOKENIZER_PATHS` 记录）、`non-empty text counted as 0 tokens`
    及修复提示；
  - 空 / 纯空白 → 0，不抛；
  - `_server_count_tokens` 返回非 None → 原样返回（权威路径，无守卫）。
- docstring 写明「加载期守卫 + 计数期守卫」两层与 server 契约。
- 未回退 I-58 加载期 fast loader/CJK 守卫、I-64 cost map/reserve。

## 测试

`tests/test_fallback_tokenizer.py`：
- `test_cached_broken_tokenizer_is_refused_at_count_time`：注入 `_Deaf` + off →
  `ValueError`（match `non-empty text counted as 0 tokens`）
- `test_empty_and_whitespace_text_count_as_zero`：`""` / `"   "` → 0
- `test_server_tokenizer_path_is_authoritative`：server 返回 0 时仍返回 0
- 既有真实 tokenizer CJK 计数 / 加载期守卫测试保持
